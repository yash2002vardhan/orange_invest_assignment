# Errand Agent

A chat agent that books, reschedules and cancels home-service errands against a mocked provider API. It never double-books, never acts without a recorded approval, and treats provider reviews as data.

## Run it (3 commands)

```bash
uv sync                                         # install (Python 3.12+)
uv run pytest                                   # 37 offline tests; writes reports/eval_table.md
OPENAI_API_KEY=sk-... uv run errand-web --reset # web UI at http://127.0.0.1:8000 (chat + live trace)
```

The web UI (`frontend/`, served by `errand_agent/web.py`) shows the chat on the left and the live trace on the right, with tabs for the mock provider's bookings and the agent's memory. **New world** wipes all state and applies the selected failure scenario. **Restart agent** rebuilds the agent on the same saved state, like a process restart.

The terminal alternative is `uv run errand-chat`, with `uv run errand-trace --latest -f` in a second pane.

### Demo recording script (about 4 min)
1. Pick scenario **timeout after success**, then click **New world**.
2. Send "Find a plumber for my kitchen tap this week, mornings only, under ₹1,500." The trace shows the model call, `search_providers`, and `collecting → choosing`.
3. Send "show reviews for 2". One review is withheld, and the trace shows `guard_check` flagging it (prompt injection handled live).
4. Send "1". The trace shows `hold_slot` and `approval_proposed`, with the price and fingerprint in the confirmation.
5. Send "yes". The trace shows `book → ERR timeout`, then `get_booking_status → booked`, then `booking_verified`. Open **Provider bookings** to show exactly one new booking.
6. Send "yes" again. The trace shows `confirmation_ignored`, and no second `book` call is made.
7. Optional: send "Cancel my AC servicing", reply "yes", and watch the 503 retry. Send "What do you remember about me?" to show stated and inferred facts.
`errand-chat --scenario timeout_after_success` forces the first `book` call to time out after the provider actually booked. Other scenarios: `slot_taken`, `price_change`, `happy`. Use `--reset` to wipe saved state.

Keys can go in a `.env` file in the project root (git-ignored). The commands load it automatically, and variables already set in your shell take precedence.

Optional:
- `JEV_API_KEY=...` (or `TYPESAFE_API_KEY`) switches the review guard from local patterns to TypeSafe's Jev decision model, called directly at `api.typesafe.ai`. An `OPENROUTER_API_KEY` routes Jev through OpenRouter instead. If a Jev call fails, the guard falls back to the patterns and records `guard_error` in the trace.
- `ERRAND_CHEAP_MODEL` / `ERRAND_STRONG_MODEL` override the routed models (defaults: `gpt-5-mini` / `gpt-5`).
- `uv run errand-bench` runs the live model-routing benchmark and writes `reports/routing_report.md`.

## Layout

```
errand_agent/
  agent.py      workflow state machine: asks, proposals, execution, recovery
  gateway.py    only path to the provider; mutating tools re-check the stored approval
  store.py      SQLite: sessions, approvals, operations (idempotency keys), memory
  memory.py     stated/inferred facts, confirmation, forget tombstones
  llm.py        typed interpretation schema, OpenAI client, scripted model, router
  guard.py      review screening (TypeSafe Jev, local patterns fallback)
  mock_api.py   the fixed tool contract, seeded failures, own SQLite file
  budget.py     per-turn caps;  tracing.py  JSONL traces with redaction
  web.py        local HTTP server for the UI (standard library only)
frontend/       index.html, styles.css, app.js: chat + live trace UI, no build step
tests/          harness + invariant checker, 26 eval scenarios, contract/unit tests
```

## Readings of ambiguous parts

- **Mock contract:** `book` takes an extra `user_id` keyword so the mock knows whose booking it is. A real API would get this from auth. `get_booking_status` covers `book` only, so cancel and reschedule are verified through `list_bookings`.
- **Price change:** a booking proposal is made after `hold_slot`, so the user approves the quoted price, not the search price. If the hold expires before execution and the new quote differs, the approval is voided and the user must approve the new price.
- **Time:** all times are naive local time (IST). Slots are 1 hour long, 08:00–19:00. A "run", for traces, is one process lifetime (one chat session or one test), and the limits apply per user turn.
- **Restarts:** an in-progress workflow (phase, collected details, options) resumes after a restart. A forgotten memory fact is also cleared from the workflow in progress.
